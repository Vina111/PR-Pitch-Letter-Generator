# 案例页库 · PDF 通路

把提案 PDF 拆到「页」入库、自动打标、跨 deck 去重、可检索，
并支持挑页组成新的案例 PDF。

## 跑起来

```bash
pip install -r requirements.txt

# 1. 建库：拆页 + 打标 + 分组 + 去重
python3 -m slidehub catalog 你的*.pdf --out build/lib

# 2. 检索
python3 -m slidehub search --year 2026 --region 北美 --industry 机器人 --library build/lib
python3 -m slidehub search 储能 --service 展会传播 --library build/lib

# 3. 挑页组成新案例（无损）
python3 -m slidehub compose --library build/lib \
  --pages "C:41,C:42,C:43,C:44,B:31" --out 欧洲家电案例.pdf

# 4. 生成可视化审阅/检索页面
python3 make_browser.py build/lib build/library.html
```

`--pages` 接受三种写法，可混用：

| 写法 | 含义 |
|---|---|
| `C:41` | C 文档第 41 页 |
| `g123` | 一个分组（一个案例的连续几页，整组带入） |
| `m046` | 一个模块（自动取默认版本） |

## 实测结果（三份美讯提案 PDF）

```
168 页  ->  162 组  ->  139 模块
22 个模块有多版本（同一案例出现在多份 deck 里）
审阅队列： 3 页疑似挂错案例 ·  51 页标签置信度偏低
组页保真： 10/10 页与源文件像素级一致
```

## 标签体系

自动打标的字段：

| 字段 | 来源 | 覆盖率 |
|---|---|---|
| 案例年份 | 正文年份，缺失时回落到文档年份 | 100% |
| 案例地区 | 地名词表（北美/欧洲/中东/东南亚/非洲…） | 77% |
| 案例行业 | 行业词表 + 品牌名推断 | 74% |
| 案例服务分类 | 服务词表（展会传播/媒体关系/社媒运维…） | 87% |
| 客户 | 品牌名词表 | 65% |
| 展会节点 | CES / IFA / MWC / GTC / RE+ / WEF … | 44% |
| 页型 | 封面 / 目录 / 过渡页 / 正文 / 正文续页 / 封底 | 100% |
| 最后一次使用 | 组页时回写，初始为空 | — |

**为什么用词表而不是模型**：这些 PDF 是 PowerPoint 导出的，文字层完整，
页面自己就写明了客户、年份、展会、市场和服务内容。词表匹配够用，
而且案例页带客户名和商业结果 —— 不外发就不用考虑保密边界；
规则可审计，标错就改一条词表；结果稳定，重跑不会把已审过的库悄悄打乱。

每个字段都带置信度，审阅从最弱的页开始，而不是从第一页开始。

## 已知需要人工确认的地方

1. **续页归属**：`策略STRATEGY` 这类没有标题的页会挂到上一页的案例。
   系统会比对续页与首页的客户名，不一致就标记（实测抓出 3 处，全部属实）。
2. **所属板块靠章节分隔页继承**：分隔页之后的页都算作该板块，直到下一个分隔页。
   若 deck 里某段案例前面没有分隔页，板块会继承错。库里就有这种情况，需人工修。
3. **结构页不打行业/客户标签**：封面、目录、过渡页、封底的行业和客户标签会被清空，
   否则它们文字里蹭到的词会污染整个库的分面计数。
